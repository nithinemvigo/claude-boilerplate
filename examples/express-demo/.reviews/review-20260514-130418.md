### Detailed Explanations

---

#### CRITICAL — Hardcoded Firebase credentials (`fb.js:4–14`)

**Context:** The `serviceAccount` object embeds a live RSA private key, `project_id`, `client_email`, and `private_key_id` directly in source code.

**Impact:** Anyone with read access to the repo gains full Firebase Admin SDK access — they can read/write all Firestore collections, impersonate any user, and manage auth. This is a supply-chain-level exposure once pushed to a remote.

**Fix:**
```js
const serviceAccount = JSON.parse(process.env.FIREBASE_SERVICE_ACCOUNT_JSON);
// or load from a secret manager at startup
```
Rotate the key immediately if this has been pushed to any remote.

---

#### CRITICAL — Plaintext password stored in Firestore (`fb.js:55–61`)

**Context:** `createUser` writes `password: password` into the Firestore document alongside the Firebase Auth record.

**Impact:** Anyone who can read the `users` collection (including via `getUserProfile` or `searchUsers`) gets plaintext credentials. Violates every compliance standard (GDPR, SOC 2, PCI).

**Fix:** Never store passwords outside the auth provider. Remove the `password` field from the Firestore write entirely.

---

#### HIGH — No `initializeApp` guard (`fb.js:17`)

**Context:** `admin.initializeApp()` is called unconditionally at module load.

**Impact:** Crashes the process with `FirebaseAppError: The default Firebase app already exists` on any hot reload (nodemon, Jest re-imports, etc.).

**Fix:**
```js
if (!admin.apps.length) {
  admin.initializeApp({ credential: admin.credential.cert(serviceAccount) });
}
```

---

#### HIGH — Unvalidated `userId` reaches Firestore (`index.js:39`)

**Context:** `url.searchParams.get('id')` returns `null` if the param is absent, and the raw string is forwarded to `db.collection('users').doc(userId)`.

**Impact:** `doc(null)` or `doc('')` will either throw or return a root-collection document, causing unexpected 500s or data leaks. No length/format check means any string (including very long inputs) hits Firestore.

**Fix:**
```js
const userId = url.searchParams.get('id');
if (!userId || !/^[a-zA-Z0-9_-]{1,128}$/.test(userId)) {
  res.writeHead(400);
  return res.end(JSON.stringify({ status: 'error', message: 'Invalid user ID' }));
}
```

---

#### HIGH — `err.message` exposed to client (`index.js:49`)

**Context:** The `.catch` handler sends `err.message` directly in the JSON response body.

**Impact:** Firebase SDK errors contain internal details: project IDs, collection paths, quota messages, and auth token hints. This feeds an attacker's enumeration effort.

**Fix:**
```js
.catch((err) => {
  logger.error('getUserProfile failed', { userId, error: err.message });
  res.writeHead(500);
  res.end(JSON.stringify({ status: 'error', message: 'Failed to retrieve user' }));
});
```

---

#### HIGH — Mass assignment in `updateUserSettings` (`fb.js:101`)

**Context:** `db.collection('users').doc(userId).update(settings)` merges the entire caller-supplied object with no filtering.

**Impact:** A caller can overwrite any field, including `role`, `email`, `password`, or `createdAt`, simply by including those keys in `settings`.

**Fix:** Maintain an explicit allowlist:
```js
const ALLOWED_SETTINGS = ['displayName', 'notificationsEnabled', 'theme'];
const safeSettings = Object.fromEntries(
  Object.entries(settings).filter(([k]) => ALLOWED_SETTINGS.includes(k))
);
await db.collection('users').doc(userId).update(safeSettings);
```

---

#### HIGH — No field allowlist in `searchUsers` (`fb.js:87`)

**Context:** `db.collection('users').where(field, '==', value)` accepts arbitrary `field` names from the caller.

**Impact:** An attacker can query `where('password', '==', 'admin123')` or `where('role', '==', 'admin')` to enumerate sensitive records.

**Fix:** Validate `field` against an allowlist before executing the query.

---

#### MEDIUM — Default role is `'admin'` (`fb.js:59`)

**Context:** Every new user is created with `role: 'admin'`.

**Impact:** Privilege escalation for all new registrations until the bug is noticed.

**Fix:** Default to `'user'` and promote explicitly.

---

#### MEDIUM — Password printed to console (`fb.js:63`)

**Context:** `console.log('Created user:', email, 'with password:', password)` appears in `createUser`.

**Impact:** Passwords land in log aggregators, stdout pipelines, and any observability tooling — visible to anyone with log access.

**Fix:** Remove the line entirely.

---

#### MEDIUM — Missing user returns `200 + {"data": null}` (`fb.js:33`, `index.js:44`)

**Context:** `getUserProfile` returns `null` when the document doesn't exist; the endpoint wraps it in a 200 response.

**Impact:** Callers cannot distinguish "not found" from "found but empty". Should be a 404.

**Fix:** Throw a `NotFoundError` from the service, or check for null in the handler and return 404.

---

#### MEDIUM — All Firestore fields returned to caller (`fb.js:38`)

**Context:** `return data` returns the entire document, which may contain `password`, `role`, internal tokens, etc.

**Fix:** Return only a safe projection:
```js
const { displayName, email, createdAt } = data;
return { displayName, email, createdAt };
```

---

#### LOW — `.DS_Store` committed

macOS metadata. Add `**/.DS_Store` to `.gitignore` and remove via:
```
git rm --cached .DS_Store
```

---

#### LOW — `deleteUser` lacks authorization check (`fb.js:74`)

Any code that calls `deleteUser(userId)` deletes the Firebase Auth record and Firestore document with no check that the caller has permission to do so.

---

#### LOW — Orders queried but never deleted (`fb.js:78`)

```js
await db.collection('orders').where('userId', '==', userId).get();
// result discarded — orders are NOT deleted
```
The orphaned orders will linger. This should use a batched delete inside a transaction with the user document deletion.

---

#### LOW — Promise chain instead of async/await (`index.js:41–50`)

Project standard (`CLAUDE.md`: "Prefer async/await over raw promises") is violated. The handler should be refactored to async/await with proper 404 handling for the null profile case.

---

#### NIT — Debug comment in production code (`index.js:40`)

`// 🐛 Issue: Using buggy service...` is a dev annotation that should not ship.
