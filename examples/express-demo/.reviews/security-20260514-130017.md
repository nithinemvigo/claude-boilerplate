#### [CRITICAL] Hardcoded Firebase Service Account — `src/services/fb.js:4`

```js
const serviceAccount = {
  private_key: '-----BEGIN RSA PRIVATE KEY-----\nMIIEpAIBAAKCAQEA0Z3VS5JJcds3...',
  client_email: 'firebase-adminsdk@my-prod-app-12345.iam.gserviceaccount.com',
  project_id: 'my-prod-app-12345',
  ...
};
```

A Firebase Admin SDK private key committed to source gives any repo reader full admin access to the Firebase project — Firestore, Auth, FCM, everything. Even if rotated after discovery, it's preserved in git history.

**Remediation:**
```js
// Store the JSON as an env var or load from a secret manager
admin.initializeApp({
  credential: admin.credential.cert(JSON.parse(process.env.FIREBASE_SERVICE_ACCOUNT)),
  databaseURL: process.env.FIREBASE_DATABASE_URL,
});
```
Immediately rotate the private key in the Firebase Console.

---

#### [CRITICAL] Plaintext Password Stored in Firestore — `src/services/fb.js:55`

```js
await db.collection('users').doc(userRecord.uid).set({
  email: email,
  password: password,   // ← raw plaintext
  role: 'admin',
  ...
});
```

Storing passwords in plaintext means a single Firestore data breach exposes every user's credential verbatim.

**Remediation:** Never store passwords. Firebase Auth manages credentials — use `userRecord.uid` as the key and store only profile data.

---

#### [HIGH] Default Role Is `admin` — `src/services/fb.js:59`

```js
role: 'admin',   // every new user is created as admin
```

Every account created through `createUser` gets full administrative privileges by default.

**Remediation:** Default to `'user'` and elevate explicitly:
```js
role: 'user',
```

#### [HIGH] Password Logged to stdout — `src/services/fb.js:63`

```js
console.log('Created user:', email, 'with password:', password);
```

Credentials written to any log aggregator (CloudWatch, Datadog, etc.) become readable by everyone with log access.

**Remediation:** Remove entirely. Never log passwords.

#### [HIGH] Unrestricted Firestore Field Query — `src/services/fb.js:87`

```js
const searchUsers = async (field, value) => {
  const snapshot = await db.collection('users').where(field, '==', value).get();
```

An attacker can pass `field='password'` to enumerate users by their stored password hash (or plaintext, given the finding above).

**Remediation:** Allowlist queryable fields:
```js
const ALLOWED_FIELDS = ['email', 'displayName'];
if (!ALLOWED_FIELDS.includes(field)) throw new Error('Invalid search field');
```

#### [HIGH] Mass Assignment — `src/services/fb.js:100`

```js
const updateUserSettings = async (userId, settings) => {
  await db.collection('users').doc(userId).update(settings);
};
```

Any caller can overwrite privileged fields like `role`, `email`, or `password` by including them in `settings`.

**Remediation:** Strip sensitive fields before writing:
```js
const { role, password, email, ...safeSettings } = settings;
await db.collection('users').doc(userId).update(safeSettings);
```

#### [HIGH] Wildcard CORS — `src/index.js:22`

```js
res.setHeader('Access-Control-Allow-Origin', '*');
```

`Access-Control-Allow-Origin: *` allows any website to make credentialed cross-origin requests to this API.

**Remediation:**
```js
const ALLOWED_ORIGINS = (process.env.ALLOWED_ORIGINS || '').split(',');
const origin = req.headers.origin;
if (ALLOWED_ORIGINS.includes(origin)) {
  res.setHeader('Access-Control-Allow-Origin', origin);
}
```

#### [MEDIUM] Unsanitized `userId` Passed to Firebase — `src/index.js:39`

```js
const userId = url.searchParams.get('id');
firebaseService.getUserProfile(userId);  // userId could be null, empty, or malformed
```

A `null` or empty `userId` causes `db.collection('users').doc(undefined)` to throw or return unexpected documents.

**Remediation:**
```js
if (!userId || typeof userId !== 'string' || userId.trim() === '') {
  res.writeHead(400);
  res.end(JSON.stringify({ error: 'Invalid user ID' }));
  return;
}
```

#### [MEDIUM] Internal Error Message Leaked — `src/index.js:49`

```js
.catch((err) => {
  res.writeHead(500);
  res.end(JSON.stringify({ error: err.message }));
});
```

Firebase SDK error messages can contain internal paths, collection names, or credential hints.

**Remediation:**
```js
.catch((err) => {
  logger.error('getUserProfile failed', { userId, error: err.message });
  res.writeHead(500);
  res.end(JSON.stringify({ error: 'Failed to retrieve user profile' }));
});
```

#### [MEDIUM] Sensitive Fields Returned Without Filtering — `src/services/fb.js:38`

```js
const data = doc.data();
return data;   // includes password, role, tokens — everything in the document
```

The entire Firestore document including any stored password or internal flags is passed back to the HTTP caller.

**Remediation:**
```js
const { password, internalToken, ...publicProfile } = doc.data();
return publicProfile;
```
