SDLC Pipeline Workflow

This is the default workflow that ships with the boilerplate. /pipeline <task> triggers the autonomous orchestrator, which delegates to 14 specialized agents, enforcing quality gates along the way.

On this page

  • Pipeline Overview
  • 14 Specialized Agents
  • Stages & Gates

Pipeline Overview

The /pipeline command handles the end-to-end SDLC autonomously. It classifies the task, asks for testing preferences, generates a plan, gets client approval, executes the code sequentially via TDD, runs tests, performs code and security reviews, and finally ships the PR.

14 Specialized Agents

The orchestrator dispatches these agents as needed:

  • Planning: planner.md, investigator.md, adr-writer.md, doc-writer.md
  • Implementation: implementer.md
  • Review: code-reviewer.md, security-reviewer.md, design-reviewer.md, eng-reviewer.md, ceo-reviewer.md
  • Testing: perf-tester.md, qa-tester.md, unit-tester.md
  • Shipping: ship-pr.md

Stages & Gates

  1. Classification: Determines nano vs standard, bug vs feature.
  2. Planning: planner or investigator creates a plan.
  3. Plan Review: ceo-reviewer, eng-reviewer, and design-reviewer evaluate the plan.
  4. Client Approval: Hard gate. You must approve the plan before execution.
  5. Execute: implementer writes code on a branch.
  6. Unit & QA Test: unit-tester and qa-tester verify behavior.
  7. Code & Security Review: code-reviewer and security-reviewer verify the diff.
  8. Ship: doc-writer updates docs, ship-pr merges and tags.
