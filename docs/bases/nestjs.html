nestjs

NestJS — opinionated backend framework with dependency injection, decorators, and modular architecture. TypeScript only.

TSbackendenterpriseDI

When to choose this base

  • You want batteries-included structure: modules, providers, controllers, guards
  • You're building a large API with multiple bounded contexts
  • You prefer Angular-style organisation on the server
  • You need first-class testability via constructor injection

If you want a lighter-weight Express setup, see express-ts.

Apply command

bash scripts/apply.sh --base=nestjs ../my-api
bash scripts/apply.sh --base=nestjs --integrations=prisma,supabase ../my-api
You still need to scaffold the NestJS project itself. Recommended flow: 
npx @nestjs/cli new my-api
cd ..
bash scripts/apply.sh --base=nestjs ./my-api

Recommended package.json scripts after apply

{
  "scripts": {
    "build": "nest build",
    "start": "node dist/main.js",
    "dev": "nest start --watch",
    "test": "jest",
    "test:e2e": "jest --config ./test/jest-e2e.json",
    "test:coverage": "jest --coverage",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write .",
    "format:check": "prettier --check .",
    "validate": "npm run lint && npm run format:check && npm run build && npm test",
    "review": "bash scripts/review.sh"
  }
}

Gotchas

  • NestJS has its own ESLint config out of the box. The base's eslint.config.js replaces it — review and merge if you've customised the original.
  • Decorator metadata requires reflect-metadata, which the NestJS scaffold already imports in src/main.ts. Don't remove it.
  • Avoid mixing @Injectable() singletons that hold per-request state. Use Scope.REQUEST deliberately.
  • The code-review hook will flag controllers with business logic — move logic into services.

Smoke test after apply

cd ../my-api
npm install
npm run dev
# in another terminal:
curl http://localhost:3000
# stop the server, then:
npm run validate
