react-vite-ts

React + Vite + TypeScript. The modern SPA starting point.

TSfrontendSPAVite

When to choose this base

  • You're building a single-page app, not a full-stack site
  • You want Vite's fast HMR and ESM-native dev server
  • Your backend lives separately (this base + express-ts on the API is a common pair)

If you need SSR, server components, or route handlers, jump to nextjs-ts.

Apply command

bash scripts/apply.sh --base=react-vite-ts ../my-app
bash scripts/apply.sh --base=react-vite-ts --integrations=tailwind,supabase ../my-app
bash scripts/apply.sh --base=react-vite-ts --integrations=firebase ../my-app   # or use --preset=firebase-react
Scaffold Vite first: 
npm create vite@latest my-app -- --template react-ts
cd ..
bash scripts/apply.sh --base=react-vite-ts ./my-app

Recommended package.json scripts after apply

{
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview",
    "test": "vitest",
    "test:coverage": "vitest run --coverage",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write .",
    "format:check": "prettier --check .",
    "validate": "npm run lint && npm run format:check && npm run build && npm test -- --run",
    "review": "bash scripts/review.sh"
  }
}

Gotchas

  • Vite's TS config splits into tsconfig.json + tsconfig.node.json. The recommended config provided here is the app-side; Vite's own node-side config stays separate.
  • The jsx-a11y ESLint plugin is strict by default. You can relax rules in eslint.config.js if false positives become noisy — but err on keeping accessibility checks on.
  • Tests use Vitest, not Jest. The generic testing.md rule references Jest patterns — they're 95% compatible (same describe/it/expect API).
  • The ui-ux-pro-max skill in core/ auto-triggers on UI work — useful here.

Smoke test after apply

cd ../my-app
npm install
npm run dev      # browser auto-opens
npm run validate
