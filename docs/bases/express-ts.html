express-ts

Node.js + Express + TypeScript. The typed Express setup.

TSbackendRESTNode 25

When to choose this base

  • You want type safety on request/response shapes
  • You're sharing types between server and a TypeScript client
  • You need refactor confidence on a growing API

If TypeScript is overkill, see express-js. If you want batteries-included structure (DI, decorators, modules), see nestjs.

Apply command

bash scripts/apply.sh --base=express-ts ../my-api
bash scripts/apply.sh --base=express-ts --integrations=prisma,supabase ../my-api

Recommended package.json scripts after apply

{
  "scripts": {
    "build": "tsc -p tsconfig.json",
    "start": "node dist/index.js",
    "dev": "tsx watch src/index.ts",
    "test": "jest",
    "test:coverage": "jest --coverage",
    "lint": "eslint .",
    "lint:fix": "eslint . --fix",
    "format": "prettier --write .",
    "format:check": "prettier --check .",
    "validate": "npm run lint && npm run format:check && npm run build && npm test",
    "review": "bash scripts/review.sh",
    "deps:audit": "npm audit --production",
    "deps:outdated": "npm outdated"
  }
}

Gotchas

  • npm run validate includes a tsc build step — this is intentional. Type errors block commits via the pre-commit hook.
  • jest uses ts-jest; tests live alongside source as *.test.ts. The generic testing.md rule says *.test.js — override that locally in your CLAUDE.md if you want.
  • tsconfig.recommended.json is a recommendation, not the file. After apply, copy values into your project's tsconfig.json (or rename).
