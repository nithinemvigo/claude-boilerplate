Bases

A base is the framework starting point. You pick exactly one per project. The base owns ESLint, tsconfig, the Node version, framework-specific rules, and the CLAUDE.md Stack/Commands/Architecture fragment.

express-js

Node.js + Express, plain JavaScript. Classic REST API setup.

JSbackendREST

express-ts

Node.js + Express + TypeScript. Typed REST APIs.

TSbackendREST

nestjs

NestJS framework — DI, decorators, modular architecture. TypeScript only.

TSbackendenterprise

react-vite-ts

React + Vite + TypeScript. Modern SPA frontend.

TSfrontendSPA

nextjs-ts

Next.js App Router + TypeScript. Full-stack React with RSC, route handlers.

TSfullstackSSR

What every base ships

The folder layout inside any overlays/bases/<base>/ is consistent:

overlays/bases/<base>/
├── .claude/rules/                  framework-specific rules layered on core
│   ├── frontend.md   | api.md     (depending on base)
│   ├── typescript.md              (TS bases only)
│   └── <framework>-conventions.md (NestJS, Next.js)
├── eslint.config.js               flat config tailored to the framework
├── tsconfig.recommended.json      TS bases only
├── .nvmrc                         Node version recommendation
├── package.scripts.json           scripts + devDeps to deep-merge into the target's package.json
├── CLAUDE.fragment.md             fills {{STACK}} / {{COMMANDS}} / {{ARCHITECTURE}} in core/CLAUDE.template.md
└── compatible-integrations.txt    whitelist of integrations apply.sh permits with this base

Choosing a base

If you're building…Pick
A REST API in plain Node + Expressexpress-js
A typed REST API on Expressexpress-ts
An enterprise-style backend (DI, modules, decorators)nestjs
A frontend-only SPAreact-vite-ts
A full-stack app with server components and route handlersnextjs-ts
Don't see your stack? v2 will add node-js, node-ts, react-js, react-ts, nextjs-js. For now, the v1 bases cover the most common modern setups.
