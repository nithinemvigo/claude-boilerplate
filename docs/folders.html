core/

The always-on layer. Every project bootstrapped from this boilerplate gets all of core/ copied into it, regardless of stack. This is what makes the agents, hooks, slash commands, skills, and generic rules work everywhere.

core/.claude/agents/

Four agent personas. Invoked with "Act as the X agent…" or by following the file directly.

FilePersonaTypical invocation
test-writer.mdQA-minded test author — emphasises edge cases and error paths over happy paths"Act as test-writer and write tests for src/components/Button.tsx"
doc-writer.mdTechnical writer — JSDoc, README updates, clear examples"Follow .claude/agents/doc-writer.md to document this module"
pr-description.mdPR author — structured descriptions from git diffAuto-invoked by the new-feature workflow at step 11
onboarding-guide.mdNew-developer guide — anticipates "where is X?" questions"Run the onboarding-guide for a new developer"

core/.claude/commands/

Seven slash commands. Available in Claude Code as /<name>.

CommandWhat it does
/changelogGenerate a CHANGELOG.md entry from recent commits, grouped by conventional-commit type
/code-reviewOn-demand multi-agent review — security, performance, accessibility, doc quality
/doc <file>Add or update JSDoc on every exported function/class/constant
/explain <file>Explain a file: purpose, data flow, dependencies, side-effects, edge cases
/feature <prd>Run the new-feature workflow against a PRD path
/prDraft a PR description from the current branch
/test <file>Generate or update tests for the target file

core/.claude/hooks/

Three shell scripts wired up by core/.claude/settings.json.

HookTriggerWhat it does
pre-commit-validate.shPreToolUse on Bash git commit4-step pipeline: ESLint → Prettier → /security-review → /code-review. Blocks the commit on failure.
post-commit-review.shPostToolUse on Bash git commitWrites a lightweight commit record to .reviews/<sha>.md
statusline.shStatus-line rendererShows project context in the Claude Code status line

core/.claude/rules/

Generic, stack-agnostic rules. Every target gets these. Stack-specific rules ship with bases (frontend.md, api.md, etc.) and integrations (supabase.md, firebase.md, etc.).

  • error-handling.md — try/catch idioms, meaningful messages, when to bubble vs. swallow
  • security.md — input validation, no hardcoded secrets, injection guards, dangerous APIs
  • environment.md — env-var conventions, .env hygiene
  • testing.md — happy/edge/error/security test buckets, coverage discipline

core/.claude/skills/ui-ux-pro-max/

Design-intelligence skill: 67 styles, 96 color palettes, 57 font pairings, 99 UX guidelines, 25 chart types, 13 technology stacks (React, Next.js, Vue, Svelte, SwiftUI, React Native, Flutter, Tailwind, shadcn/ui…). Auto-triggers on UI-related work ("design a landing page", "build a dashboard", "choose a color palette").

core/.agents/workflows/

End-to-end playbooks Claude can execute step by step.

WorkflowWhat it coversHow to run
new-feature.md 11 steps, PRD → PR. Uses /office-hours, /plan-ceo-review, /brainstorm, /plan-eng-review, /write-plan, /execute-plan, /ship (gstack + superpowers plugins), with pr-description.md as fallback. /feature path/to/prd.md or "Follow .agents/workflows/new-feature.md to implement <X>"
dependency-update.md Audit → fix vulns → update outdated → run tests → commit. Branch-based. "Follow .agents/workflows/dependency-update.md"

core/.editorconfig, .prettierrc, .prettierignore

Stack-agnostic editor and formatting defaults. Every target gets these as a starting point.

overlays/

The pick-and-mix layer. Every target chooses exactly one base and zero or more integrations. Overlays are not copied automatically; apply.sh selects them based on flags.

overlays/bases/

Framework-specific files. One per project. See Bases for full per-base detail.

  • express-js/ — Node + Express, plain JavaScript
  • express-ts/ — Node + Express, TypeScript
  • nestjs/ — NestJS (TS-only)
  • react-vite-ts/ — React + Vite + TypeScript
  • nextjs-ts/ — Next.js App Router + TypeScript

Each base contains:

  • .claude/rules/ — framework-specific rules layered on top of core/.claude/rules/
  • eslint.config.js — flat config tailored to the framework
  • tsconfig.recommended.json (TS bases only) — sane TS defaults
  • .nvmrc — Node version
  • package.scripts.json — scripts and devDeps to deep-merge into the target's package.json
  • CLAUDE.fragment.md — text that fills {{STACK}} / {{COMMANDS}} / {{ARCHITECTURE}} in the template
  • compatible-integrations.txt — whitelist of integrations apply.sh permits with this base

overlays/integrations/

Additive layers. Zero or more per project. See Integrations for full detail.

  • supabase/ — Postgres + Auth + Storage + Realtime
  • firebase/ — Auth + Firestore + Storage
  • tailwind/ — Utility-first CSS
  • prisma/ — Type-safe ORM

Each integration contains only additive content:

  • .claude/rules/<name>.md — team idioms and pitfalls for this integration
  • env.snippet — env-var keys to append to .env.example
  • architecture.md — paragraph appended to CLAUDE.md
  • package.snippet.json — devDeps and scripts to merge
  • compatible-with.txt — bases this integration supports
Critical constraint: integrations never overwrite a file already owned by core/ or the base. apply.sh aborts on file conflicts. This is what keeps composition safe.

presets/

Named base + integrations bundles. Three v1 presets:

PresetExpands to
t3-stack.json--base=nextjs-ts --integrations=tailwind,trpc,prisma,nextauth,zod
supabase-nextjs.json--base=nextjs-ts --integrations=supabase
firebase-react.json--base=react-vite-ts --integrations=firebase

Add a new preset by dropping a JSON file in this folder. Schema is small:

{
  "name": "my-preset",
  "description": "Short blurb",
  "base": "<base name>",
  "integrations": ["a", "b"],
  "tags": ["fullstack", "..."]
}

examples/

Runnable demos. Used to show the pre-commit pipeline in action.

examples/express-demo/

The original Express API (formerly src/ at the repo root). Contains deliberate bugs — SQL injection in the admin route, hardcoded secret in the FB service — so the security and code-review hooks have something to catch. .reviews/ beside it stores historical review reports from past commits.

Run cd examples/express-demo && npm install && npm test to see the demo green-light, then try git commit on a deliberate vuln to see the pre-commit pipeline block it.

docs/

This documentation site. Plain HTML, no build step.

  • index.html — landing page
  • folders.html — this page
  • apply.html — apply.sh contract, combinations, compatibility matrix
  • bases/ — one HTML page per base
  • integrations/ — one HTML page per integration
  • presets/ — one HTML page per preset
  • assets/styles.css — shared stylesheet
  • apply-composition.md — Markdown version of the apply contract (for GitHub rendering)

scripts/

Repo-level tooling.

  • apply.sh — the composer (the script every section above keeps referencing). Validates the combo, copies core, copies the base, copies integrations, merges package.json, renders CLAUDE.md, appends .env.example. See Apply for the full contract.

The demo's review.sh lives at examples/express-demo/scripts/review.sh — it's part of the demo, not a repo-level tool.
