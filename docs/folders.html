core/

The always-on layer. Every project bootstrapped from this boilerplate gets all of core/ copied into it, regardless of stack. This is what makes the agents, hooks, slash commands, and generic rules work everywhere.

core/.claude/agents/

Fourteen specialized agents. They form an autonomous SDLC pipeline orchestrated by .claude/commands/pipeline.md. The orchestrator dispatches them as needed.

CategoryAgents
Planningplanner.md, investigator.md, adr-writer.md, doc-writer.md
Implementationimplementer.md
Reviewcode-reviewer.md, security-reviewer.md, design-reviewer.md, eng-reviewer.md, ceo-reviewer.md
Testingperf-tester.md, qa-tester.md, unit-tester.md
Shippingship-pr.md

core/.claude/commands/

One slash command. Available in Claude Code as /<name>.

CommandWhat it does
/pipeline <description>Autonomous SDLC Orchestrator. End-to-end feature/bug pipeline. Ask type + testing prefs → Plan (features) or Investigate (bugs) → reviews → CLIENT APPROVES PLAN → Execute (TDD if requested) → Unit test → QA → Code+Security review → Docs → Ship PR.

core/.claude/hooks/

Four shell scripts wired up by core/.claude/settings.json.

HookTriggerWhat it does
pre-commit-validate.shPreToolUse on Bash git commit4-step pipeline: ESLint → Prettier → /security-review → /code-review. Missing-plugin gates degrade to a warning by default (set CLAUDE_BOILERPLATE_STRICT=1 to fail hard).
plugin-probe.shCalled by pre-commit-validate.shDetects whether security-guidance and code-review plugins are installed.
post-commit-review.shPostToolUse on Bash git commitWrites a lightweight commit record to .reviews/<sha>.md.
statusline.shStatus-line rendererShows project context in the Claude Code status line.

core/.claude/rules/

Generic, stack-agnostic rules. Every target gets these. Stack-specific rules ship with bases (api.md, frontend.md, etc.) and integrations (supabase.md, firebase.md, etc.).

  • error-handling.md — try/catch idioms, meaningful messages, when to bubble vs. swallow
  • security.md — input validation, no hardcoded secrets, injection guards, dangerous APIs
  • environment.md — env-var conventions, .env hygiene
  • testing.md — happy/edge/error/security test buckets, coverage discipline

core/scripts/

Scripts that ship to every target project. Don't confuse these with scripts/ at the repo root (which is for the boilerplate itself).

  • check-setup.sh — verifies Node version, claude CLI, plugin installation, hook wiring, and .env state. Run as npm run check-setup in target projects.
  • review.sh — manual /code-review on the last commit. Run as npm run review.

core/.editorconfig, .prettierrc, .prettierignore

Stack-agnostic editor and formatting defaults. Every target gets these as a starting point.

core/CLAUDE.template.md

The template that becomes the target project's CLAUDE.md. Has four placeholders filled by the base fragment: {{STACK}}, {{COMMANDS}}, {{ARCHITECTURE}}, {{ANTIPATTERNS}}. Integration architecture paragraphs are appended at the bottom.

overlays/

The pick-and-mix layer. Every target chooses exactly one base and zero or more integrations. Overlays are not copied automatically; apply.sh selects them based on flags.

overlays/bases/

Framework-specific files. One per project. See Bases for full per-base detail.

  • express-js/ — Node + Express, plain JavaScript
  • express-ts/ — Node + Express, TypeScript
  • nestjs/ — NestJS (TS-only)
  • react-vite-ts/ — React + Vite + TypeScript
  • nextjs-ts/ — Next.js App Router + TypeScript

Each base contains:

  • .claude/rules/ — framework-specific rules layered on top of core/.claude/rules/
  • eslint.config.js — flat config tailored to the framework
  • tsconfig.recommended.json (TS bases only) — sane TS defaults
  • .nvmrc — Node version
  • package.scripts.json — scripts and devDeps to deep-merge into the target's package.json
  • CLAUDE.fragment.md — text that fills {{STACK}} / {{COMMANDS}} / {{ARCHITECTURE}} / {{ANTIPATTERNS}} in the template
  • compatible-integrations.txt — whitelist of integrations apply.sh permits with this base

overlays/integrations/

Additive layers. Zero or more per project. See Integrations for full detail.

  • supabase/ — Postgres + Auth + Storage + Realtime
  • firebase/ — Auth + Firestore + Storage
  • tailwind/ — Utility-first CSS
  • prisma/ — Type-safe ORM

Each integration contains only additive content:

  • .claude/rules/<name>.md — team idioms and pitfalls for this integration
  • env.snippet — env-var keys to append to .env.example
  • architecture.md — paragraph appended to CLAUDE.md
  • package.snippet.json — devDeps and scripts to merge
  • compatible-with.txt — bases this integration supports
Critical constraint: integrations never overwrite a file already owned by core/ or the base. apply.sh aborts on file conflicts. This is what keeps composition safe.

presets/

Named base + integrations bundles. Three v1 presets:

PresetExpands to
t3-stack.json--base=nextjs-ts --integrations=tailwind,trpc,prisma,nextauth,zod
supabase-nextjs.json--base=nextjs-ts --integrations=supabase
firebase-react.json--base=react-vite-ts --integrations=firebase

Add a new preset by dropping a JSON file in this folder. Schema is small:

{
  "name": "my-preset",
  "description": "Short blurb",
  "base": "<base name>",
  "integrations": ["a", "b"],
  "tags": ["fullstack", "..."]
}

examples/

Runnable demos. Used to show the pre-commit pipeline in action.

examples/express-demo/

A demo Express API. Contains deliberate bugs — SQL injection in the admin route, hardcoded secret in the FB service — so the security and code-review hooks have something to catch. .reviews/ beside it stores historical review reports from past commits.

Run cd examples/express-demo && npm install && npm test to see the demo green-light, then try git commit on a deliberate vuln to see the pre-commit pipeline block it.

docs/

This documentation site. Plain HTML, no build step.

  • index.html — landing page (interactive stack builder)
  • folders.html — this page
  • apply.html — apply.sh contract, combinations, compatibility matrix
  • bases/ — one HTML page per base
  • integrations/ — one HTML page per integration
  • presets/ — one HTML page per preset
  • assets/styles.css — shared stylesheet
  • apply-composition.md — Markdown version of the apply contract (for GitHub rendering)

scripts/

Repo-level tooling. Not copied into target projects (use core/scripts/ for things that ship to every target).

  • apply.sh — the composer. Validates the combo, copies core, copies the base, copies integrations, merges package.json, renders CLAUDE.md, appends .env.example. Best for new project directories. See Apply for the full contract.
  • apply-to-existing.sh — safe-merge wrapper for existing repos. Stages a full apply, then copies only files the target doesn't have. Auto-appends unique lines to .gitignore and .env.example. Prints a per-file merge plan for files that already exist (e.g. package.json deep-merge instructions). Preserves a staging copy at .claude-boilerplate-staging/ for diffing.
