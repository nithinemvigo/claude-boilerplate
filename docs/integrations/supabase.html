supabase

Postgres + Auth + Storage + Realtime as a hosted backend. The integration adds team idioms and pitfalls — not the SDK itself, which you install with npm i @supabase/supabase-js.

databaseauthstoragerealtime

Environment variables

# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
# Server-only — must NEVER be exposed to the browser:
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
Service role key is dangerous. It bypasses RLS. Only use it on the server, inside route handlers or server actions. core/.claude/rules/security.md + supabase.md both flag misuse.

Rule file highlights (supabase.md)

  • RLS is mandatory. Every new table gets a policy. "It works because RLS is off in dev" is a bug.
  • Anon key in the client, service role on the server. Never the reverse. The pre-commit security review flags hardcoded service-role keys.
  • Realtime channels must unsubscribe. In React, return a cleanup from useEffect.
  • Generate types. Run supabase gen types typescript --project-id <ref> > src/types/supabase.ts and commit the output.
  • Auth flow. For Next.js, use @supabase/ssr's cookies adapter; refresh tokens automatically in middleware.
  • Storage URLs. Public buckets are public; signed URLs expire — verify TTL.

Combined with other integrations

  • + prisma — use Prisma as the ORM with Supabase Postgres as the DB. The Supabase JS client is still useful for Auth and Storage.
  • + tailwind on a frontend base — standard SaaS pattern.
  • + trpc (v2) — RLS still applies at the SQL layer regardless of the transport.

Gotchas

  • Migrations live in supabase/migrations/ (created by supabase init). Don't edit deployed migrations — add new ones.
  • The NEXT_PUBLIC_* prefix is required for keys that reach the browser. SUPABASE_SERVICE_ROLE_KEY intentionally lacks the prefix.
  • Edge functions are not covered by this integration — they're a separate concern. Add a supabase-functions.md rule if you use them heavily.
