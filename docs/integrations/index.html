Integrations

Integrations are additive overlays — they layer on top of a base, adding a rule file, env vars, and an Architecture paragraph. They never overwrite anything the base already wrote. Pick zero or more per project.

The additive-only contract

Every integration must follow this rule: only add new files, never overwrite. If an integration ships a file with the same path as a base or core file, apply.sh aborts with exit code 3. This guarantee is what lets you mix integrations safely.

What an integration can ship:

  • A new rule file at .claude/rules/<name>.md (never overlaps with core or base rule names)
  • An env.snippet with env-var keys to append to .env.example
  • An architecture.md paragraph appended to the project's CLAUDE.md
  • A package.snippet.json with new devDeps / scripts to merge into package.json
  • A compatible-with.txt listing the bases it supports
  • (Optional, v2) A starter/ directory with scaffolding code, applied only when --starter is passed

Common combinations

  • supabase + tailwind on nextjs-ts — fast Supabase-backed SaaS UI
  • firebase + tailwind on react-vite-ts — see the firebase-react preset
  • prisma + supabase on nestjs — Prisma as the ORM, Supabase Postgres as the database
  • tailwind + prisma on nextjs-ts — half of the T3 stack
