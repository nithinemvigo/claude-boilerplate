supabase-nextjs

Next.js App Router + TypeScript + Supabase. Postgres + Auth + Storage + Realtime behind an SSR-capable React app.

fullstacksupabasepostgresv1

What it expands to

bash scripts/apply.sh --preset=supabase-nextjs ../my-app
# equivalent to:
bash scripts/apply.sh --base=nextjs-ts --integrations=supabase ../my-app

When to use this preset

  • You want Postgres + Auth in one BaaS, server-rendered on Next.js
  • You're shipping a SaaS, internal tool, or product with auth-gated data
  • You want RLS as your authorization layer (database-enforced, application-aware)

Add tailwind on top for a SaaS UI:

bash scripts/apply.sh --base=nextjs-ts --integrations=supabase,tailwind ../my-app

What lands

  • Base: nextjs-ts — full Next.js App Router setup, frontend + api rules, strict TS
  • Integration: supabase — supabase.md rule, env keys, Architecture paragraph

Environment variables

# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>   # server-only

Recommended workflow

  1. Scaffold Next.js: npx create-next-app@latest my-app --typescript --app --tailwind --eslint
  2. Apply the preset: bash scripts/apply.sh --preset=supabase-nextjs ../my-app
  3. Install the Supabase clients: npm install @supabase/supabase-js @supabase/ssr
  4. Initialise Supabase locally: npx supabase init → migrations in supabase/migrations/
  5. Write your first RLS policy before you build the feature that needs it
  6. Generate types: npx supabase gen types typescript --project-id <ref> > src/types/supabase.ts

Architecture sketch

my-app/
├── app/
│   ├── layout.tsx
│   ├── page.tsx
│   └── api/                       Route Handlers — use service-role client carefully
├── src/
│   ├── lib/
│   │   └── supabase/
│   │       ├── client.ts          Browser client (anon key)
│   │       ├── server.ts          Server client (cookies adapter via @supabase/ssr)
│   │       └── service.ts         Service-role client (server-only)
│   └── types/
│       └── supabase.ts            Generated types
├── supabase/
│   ├── config.toml
│   └── migrations/                Schema + RLS policies as SQL files
└── .claude/                       From core + nextjs-ts base + supabase integration

Common follow-ups

  • Add tailwind for styling
  • Add prisma if you prefer an ORM over the Supabase JS client (still keep Supabase Auth + Storage)
