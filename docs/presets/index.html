Presets

A preset is a named alias for a base + list of integrations. Presets ship no new content of their own — they just save you from typing the full combination on the command line. Drop a JSON file in presets/ to add a new one.

How presets work

A preset JSON looks like this:

{
  "name": "supabase-nextjs",
  "description": "Next.js App Router + TypeScript + Supabase",
  "base": "nextjs-ts",
  "integrations": ["supabase"],
  "tags": ["fullstack", "supabase"]
}

When you run apply.sh --preset=<name>, the script:

  1. Reads presets/<name>.json
  2. Expands it to the equivalent --base=<base> --integrations=<a,b,c>
  3. Runs the normal apply flow (validation, copy core, copy base, copy integrations, merge, render)

Adding a new preset

  1. Create presets/<your-name>.json with the schema above.
  2. Run bash scripts/apply.sh --preset=<your-name> --dry <some-target> to verify the expansion.
  3. Add a page in docs/presets/<your-name>.html if you want it documented (recommended for shared presets).
Presets are also a good place to encode team conventions. "At ACME, every Next.js app uses Supabase + Tailwind" → that's a preset.
