Claude Boilerplate

A composable Claude Code starter. One core/ of agents, commands, hooks and skills, plus stack-specific bases (Express, NestJS, React, Next.js…) and additive integrations (Supabase, Firebase, Tailwind, Prisma…). One command stitches them into any new project.

Quick start

bash scripts/apply.sh --base=nextjs-ts --integrations=supabase,tailwind ../my-app

Or pick a preset — --preset=t3-stack, --preset=supabase-nextjs, --preset=firebase-react. See Apply for the full contract.

The composition model

Every project bootstrapped from this boilerplate is built from three layers, applied in order:

LayerHow manyOwns
core/ always one Stack-agnostic agents, commands, hooks, skills, generic rules, the CLAUDE.md template, and editor configs.
Base overlays/bases/<name> exactly one per project Framework files: ESLint config, tsconfig, .nvmrc, package.json scripts, framework-specific rules, and the CLAUDE.md fragment.
Integrations overlays/integrations/<name> zero or more Additive only. A rule file, env-var keys for .env.example, and an Architecture paragraph appended to CLAUDE.md. Never overwrites base files.

Presets (presets/<name>.json) are named aliases that expand to a base plus a list of integrations. They add no new content of their own.

How combinations work

Example 1 — React TS + Supabase

bash scripts/apply.sh --base=react-ts --integrations=supabase ../my-app

What lands:

  • core/ — everything stack-agnostic
  • overlays/bases/react-ts/ — frontend.md, typescript.md, React ESLint config, tsconfig, scripts
  • overlays/integrations/supabase/ — supabase.md rule, env keys, Architecture paragraph in CLAUDE.md, optional src/lib/supabase.ts starter
react-ts is v2 — use react-vite-ts for v1.

Example 2 — Next.js TS + Firebase + Tailwind

bash scripts/apply.sh --base=nextjs-ts --integrations=firebase,tailwind ../my-app

Two integrations layered in the order listed. Order only affects the rendered CLAUDE.md Architecture section.

Example 3 — T3 Stack (a preset)

bash scripts/apply.sh --preset=t3-stack ../my-app
# equivalent to:
# --base=nextjs-ts --integrations=tailwind,trpc,prisma,nextauth,zod

Presets are just named aliases for base + integrations.

Example 4 — NestJS + Prisma + Supabase

bash scripts/apply.sh --base=nestjs --integrations=prisma,supabase ../my-app

The apply.sh contract

For the full step-by-step contract, compatibility matrix, error model, and FAQ, see Apply. Short version:

  1. Validate the combo (hard error on impossible pairs, warn on unusual ones).
  2. Copy core/ to the target.
  3. Copy overlays/bases/<base>/ on top.
  4. Copy each integration in order — aborting if any tries to overwrite a base file.
  5. Deep-merge package.json scripts and devDependencies.
  6. Render CLAUDE.md from the template + base fragment + integration paragraphs.
  7. Append .env.example keys.
  8. Print a summary.
  9. --dry shows the plan without writing anything.
