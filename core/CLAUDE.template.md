## Coding Standards

- Use `const` by default, `let` when mutation is needed, never `var`.
- Prefer `async`/`await` over raw promises.
- Error handling: always use try/catch with meaningful messages — see `.claude/rules/error-handling.md`.
- Naming: `camelCase` for variables/functions, `PascalCase` for classes/types, `SCREAMING_SNAKE` for constants.
- Max function length: 30 lines — refactor if exceeding.
- Max file length: 300 lines — split into modules if exceeding.
- Prefer pure functions and explicit dependencies. Side-effects live in clearly-named modules.

## Claude Hooks

Hooks fire automatically during Claude Code sessions. Configured in `.claude/settings.json`.

### Pre-commit pipeline (on every `git commit`)

1. **ESLint** — blocks on lint errors.
2. **Prettier check** — blocks on formatting drift.
3. **`/security-review`** — blocks on injection, XSS, eval, hardcoded secrets, path traversal.
4. **`/code-review`** — blocks if verdict is "Request Changes" or critical issues found.

Reports save to `.reviews/<commit-sha>.md` automatically.

> Tip: `npm run lint:fix && npm run format` auto-fixes most blockers before commit.

### Manual review

- `/code-review` — on-demand multi-agent review of a file or commit.
- `npm run review` (if scripted) — review the last commit.
